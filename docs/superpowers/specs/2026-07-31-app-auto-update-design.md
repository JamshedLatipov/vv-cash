# Автообновление кассы

**Дата:** 2026-07-31
**Репозиторий:** `vv-cash` (клиент)
**Статус:** дизайн утверждён, ждёт ревью спеки

## Контекст и проблема

Новая версия кассы доезжает до магазина так: сборщик запускает
[`build/installer/build_installer.ps1`](../../../build/installer/build_installer.ps1),
получает `build/installer/Output/VvCashInstaller.exe` и руками заливает его на
`https://proffi.io/downloads/proffi-kassa-setup.exe`. Дальше кассир должен сам
зайти на [центр загрузок](https://proffi.io/#/downloads), заметить, что версия
поменялась, скачать и переустановить.

Заметить он этого не может. На странице загрузок версия — `v1.0.0` — зашита в
вёрстку сайта, а у самой кассы версии нет вообще: `<Version>` в
[`VvCash.csproj`](../../../src/VvCash/VvCash.csproj) отсутствует, единственное
место, где `1.0.0` вообще написано, — строка `AppVersion` в
[`VvCashInstaller.iss`](../../../build/installer/VvCashInstaller.iss). Запущенное
приложение не знает собственной версии и не может сравнить её ни с чем.

Отсюда: **парк касс разъезжается по версиям, и никто — ни кассир, ни мы — не
видит, какая где стоит.** Исправление, выпущенное сегодня, доедет до магазина
тогда, когда кто-то вспомнит про него вручную.

**Цель:** касса сама узнаёт о новой версии, показывает это кассиру и ставит
обновление по его команде.

## Условия задачи

Зафиксировано при обсуждении дизайна:

- раздача — статические файлы на `proffi.io`, все кассы ходят в облако, локальных
  серверов в магазинах нет;
- кассир на своей машине — локальный администратор, значит приложение может
  запустить инсталлятор без запроса UAC;
- обновление ставится **по решению кассира**, а не молча: фоновая проверка,
  ненавязчивый индикатор, кнопка. Принудительных обновлений в этом объёме нет;
- сертификата Authenticode нет и в ближайшее время не будет.

## Решение

Инсталлятор Inno Setup остаётся ровно тем, что есть. Приложение получает
собственный апдейтер: раз в час забирает манифест, сравнивает версии, показывает
индикатор, по нажатию качает тот же `proffi-kassa-setup.exe`, сверяет SHA-256 и
запускает его в тихом режиме.

Не Velopack и не Squirrel: они ставят приложение в `%LocalAppData%` для текущего
пользователя, а касса стоит в `Program Files`. Переезд означал бы миграцию уже
установленного парка — риск несоразмерный выигрышу от дельта-обновлений.
Тридцать четыре мегабайта раз в пару недель на кассе с обычным интернетом не
болят.

Не NetSparkle: это тот же подход, но библиотекой, ради примерно трёхсот строк
кода. Взамен — своя зависимость, свой формат appcast и чужой интерфейс мимо
дизайн-системы, притом что окно и индикатор всё равно пришлось бы делать своими.

## Безопасность

Автообновление превращает кассу в исполнитель произвольного `.exe` с правами
администратора. Дизайн исходит из этого прямо.

**Что защищает.** Манифест и файл берутся только по `https`, без отката на `http`
и без ослабления проверки сертификата. SHA-256 скачанного файла сверяется с
хешем из манифеста **до** запуска; не сошлось — файл удаляется, установка не
начинается.

**Что не защищает.** Хеш подтверждает целостность доставки, но не подлинность
источника: злоумышленник, получивший доступ к `proffi.io`, подменит и файл, и
манифест разом, и хеш сойдётся. Authenticode закрыл бы это, но сертификата нет,
и риск принят осознанно.

Задел на потом: подпись самого манифеста собственным ключом (Ed25519), публичный
ключ вшит в приложение. Это закрывает подмену на сервере бесплатно и ложится
поверх описанной схемы без её переделки — добавляется поле `signature` и одна
проверка. В текущий объём не входит.

**Токен кассы на proffi.io не уходит.** Все `HttpClient` приложения цепляют
[`AuthHeaderHandler`](../../../src/VvCash/Services/Api/AuthHeaderHandler.cs)
([`App.axaml.cs`](../../../src/VvCash/App.axaml.cs)); клиент апдейтера
регистрируется **без** него. `proffi.io` — не API кассы, и `Bearer` там не нужен.

## Архитектура

### Версия сборки

Источник истины переезжает в
[`VvCash.csproj`](../../../src/VvCash/VvCash.csproj):

```xml
<Version>1.0.0</Version>
```

`VvCashInstaller.iss` перестаёт хардкодить `AppVersion` и берёт версию из
собранного `VvCash.exe` — Inno Setup умеет это через `GetVersionNumbersString`.
После правки выпуск новой версии — это изменение одной строки в csproj.

### Каталог `Services/Update/`

**`IAppVersionProvider`** — отдаёт версию текущей сборки:

```csharp
public interface IAppVersionProvider
{
    Version Current { get; }
}
```

Реализация читает `Assembly.GetEntryAssembly()`. Обёртка тонкая, но без неё
версию в тестах не подделать, а вся логика сравнения строится на ней.

**`UpdateInfo`** — то, что апдейтер сообщает наружу:

```csharp
public sealed record UpdateInfo(
    Version Version,
    string Url,
    string Sha256,
    long SizeBytes,
    string? Notes);
```

**`IUpdateService`**:

```csharp
public interface IUpdateService
{
    Task<UpdateInfo?> CheckAsync(CancellationToken ct);
    Task<string?> DownloadAsync(UpdateInfo info, IProgress<double>? progress, CancellationToken ct);
}
```

`CheckAsync` возвращает `null`, если обновления нет **или** если с сервером
что-то не так — для вызывающего это одно и то же состояние. `DownloadAsync`
возвращает путь к проверенному файлу либо `null`, если хеш не сошёлся или
скачивание сорвалось.

**`IInstallerLauncher`** — прячет `Process.Start`, чтобы тесты не запускали
инсталлятор:

```csharp
public interface IInstallerLauncher
{
    void Launch(string installerPath);
}
```

Реализация запускает `installerPath` с аргументами
`/VERYSILENT /SUPPRESSMSGBOXES /NORESTART` и `UseShellExecute = true`. Дочерний
процесс переживает выход родителя, поэтому приложение сразу после запуска
инсталлятора завершается через `IClassicDesktopStyleApplicationLifetime.Shutdown`
— иначе Inno не сможет переписать занятый `VvCash.exe`.

### Правка инсталлятора: возврат приложения после тихой установки

В [`VvCashInstaller.iss`](../../../build/installer/VvCashInstaller.iss) строка
запуска приложения помечена флагом `skipifsilent`. Флаг делает ровно то, что
написано: при `/VERYSILENT` запись `[Run]` пропускается. То есть после тихого
обновления касса не поднимется — кассир будет смотреть на закрывшуюся программу
и звонить в поддержку.

Флаг снимается, но не с существующей записи: у неё есть ещё и `postinstall`,
из-за которого при обычной ручной установке она показывается галочкой на
последней странице мастера, и это поведение надо сохранить. Поэтому записей
становится две:

- прежняя, с `postinstall skipifsilent` — галочка «Запустить VvCash» для того,
  кто ставит программу руками;
- новая, с `nowait` и без `postinstall`, под условием `Check: WizardSilent` —
  срабатывает только при тихой установке, то есть только при автообновлении.

Условие обязательно: без него при ручной установке приложение запустится дважды.

### Манифест

`https://proffi.io/downloads/kassa-latest.json`, заливается тем же движением, что
и `proffi-kassa-setup.exe`:

```json
{
  "product": "vvcash",
  "version": "1.1.0",
  "url": "https://proffi.io/downloads/proffi-kassa-setup.exe",
  "sha256": "9f2b1c4a7e35d081bc6f42a90e5713d8cf20ab6749e83c15d02f7ba418c69e3d",
  "sizeBytes": 35651584,
  "releasedAt": "2026-08-05",
  "notes": "Возвраты с обменом, формат телефона"
}
```

### Валидация манифеста

`proffi.io` — SPA: на любой несуществующий путь сервер отдаёт `index.html` с
кодом **200**. Проверено на `/downloads/manifest.json` — вернулся HTML под
успешным статусом. Наивный апдейтер получит страницу, не увидит ошибки и
попытается разобрать её как JSON. Поэтому проверок несколько, и любая
несработавшая означает «обновления нет»:

1. `Content-Type` ответа начинается с `application/json`;
2. тело разбирается как JSON без исключений;
3. `product` равно `vvcash`;
4. `version` разбирается в `System.Version`;
5. `url` — абсолютный и обязательно со схемой `https`;
6. `sha256` — ровно 64 шестнадцатеричных символа.

Хост из `url` с хостом манифеста намеренно не сверяется: файл и манифест лежат
рядом, а лишнее правило усложнило бы возможный переезд раздачи на CDN.

### Куда встраивается проверка

Фоновый цикл уже существует —
[`PosViewModel.StartBackgroundSync`](../../../src/VvCash/ViewModels/PosViewModel.cs)
крутится каждые десять секунд и по своему интервалу дёргает синхронизацию
товаров и ростер продавцов. Проверка обновлений добавляется туда же, третьим
делом с собственным интервалом — **раз в час**, первая проверка через минуту
после старта, чтобы не толкаться с логином и первичной синхронизацией.

Отдельного таймера не заводим: цикл уже умеет останавливаться по
`CancellationToken` при выходе, и второй механизм жизненного цикла здесь лишний.

Следствие, принятое сознательно: проверка идёт только после входа кассира, когда
`PosViewModel` живёт. На экране логина обновления не ищутся. Касса стоит
включённой весь рабочий день, так что час ожидания после входа ничего не
задерживает, а проверять до логина незачем — ставить обновление всё равно
некому.

### Состояние во вьюмодели

`PosViewModel` получает:

- `IsUpdateAvailable` — виден ли индикатор;
- `AvailableUpdate` — найденный `UpdateInfo`;
- `IsUpdateModalVisible`, `UpdateDownloadProgress`, `UpdateErrorText`;
- `CanInstallUpdate` — вычисляемое: `false`, пока корзина непуста;
- команды `OpenUpdateModal`, `StartUpdate`, `CancelUpdate`, `DismissUpdate`.

## Интерфейс

### Индикатор

Статус-бар внизу
[`PosView.axaml`](../../../src/VvCash/Views/PosView.axaml) уже держит ровно такие
индикаторы — состояние связи, принтер, несинхронизированные документы. Индикатор
обновления встаёт туда четвёртым и повторяет паттерн соседа
`HasUnsyncedDocuments`: `IsVisible` по флагу, `MaterialIcon`, короткий текст.
Отличие одно — по нему можно кликнуть.

### Настоящая версия вместо мокапной

В правом углу того же статус-бара висит ключ `V240TERMINALIDLXP099` со значением
`"V 2.4.0 • TERMINAL ID: LXP-09921"` — остаток от макета, не связанный ни с
какой реальностью. Раз появляется `IAppVersionProvider`, строка заменяется на
настоящую версию сборки. Кассир и служба поддержки наконец видят, что стоит на
машине.

### Окно обновления

По клику на индикатор — модальное окно в стиле существующих (тот же приём, что у
`IsShiftModalVisible`): номер версии, размер, заметки к выпуску, кнопки
«Обновить» и «Позже».

- «Позже» закрывает окно, индикатор остаётся висеть. Повторно не навязываемся.
- «Обновить» показывает прогресс скачивания; кнопка «Отмена» работает всё это
  время.
- После успешной проверки хеша — предупреждение, что программа закроется, затем
  запуск инсталлятора и выход.

### Защита от обновления не вовремя

Кнопка «Обновить» заблокирована, пока в корзине есть позиции, с подписью
«Завершите текущий чек». Обрывать пробитие чека перезапуском недопустимо.

Открытую смену **не** блокируем: смена живёт на сервере, и после перезапуска
[`IShiftService.GetShiftStateAsync`](../../../src/VvCash/Services/Api/IShiftService.cs)
поднимет её обратно.

### Локализация

Новые ключи добавляются во все пять файлов
[`src/VvCash/Assets/i18n`](../../../src/VvCash/Assets/i18n): `en`, `kk`, `ru`,
`tg`, `uz`.

## Обработка ошибок

Принцип: неполадки с сервером обновлений — не забота кассира. Касса торгует, а не
жалуется на `proffi.io`.

| Что случилось | Что делает касса |
|---|---|
| Нет сети, таймаут, 404, невалидный манифест | Молчит. Индикатор не появляется, следующая попытка через час |
| SHA-256 не совпал | Удаляет файл, показывает «не удалось проверить целостность обновления», пишет в лог |
| Скачивание оборвалось или отменено | Удаляет недокачанный файл, предлагает «Повторить» |
| Инсталлятор не запустился (`Win32Exception`) | Показывает путь к скачанному файлу, чтобы его запустили вручную |

Временные файлы — `%TEMP%\VvCash\updates\`; каталог чистится в начале каждой
проверки, так что оборванная закачка не копится на диске.

Таймауты: на манифест — десять секунд; на скачивание общего таймаута нет, его
роль играет `CancellationToken`, привязанный к кнопке «Отмена».

## Тестирование

xUnit, существующий
[`StubHttpMessageHandler`](../../../tests/VvCash.Tests/StubHttpMessageHandler.cs)
подходит без изменений. Двойники: `IAppVersionProvider` подделывает текущую
версию, `IInstallerLauncher` не даёт тестам запустить инсталлятор.

**`UpdateServiceTest` — разбор манифеста.** Версия новее текущей даёт
`UpdateInfo`; равная и более старая дают `null`. Отдельными тестами — каждая
причина отказа: HTML вместо JSON под кодом 200 (та самая ловушка SPA), чужой
`product`, схема `http` вместо `https`, `sha256` неверной длины или с
не-hex-символами, битый JSON, сетевая ошибка.

**`UpdateServiceTest` — скачивание.** Хеш совпал → возвращается путь, файл на
месте. Хеш не совпал → возвращается `null` **и файла на диске не остаётся**.

**`PosViewModel`.** Непустая корзина → `CanInstallUpdate == false`. Пустая →
`true`.

Запуск: `& ./run-tests.ps1` (без `pwsh`, его на машине сборки нет).

## Границы объёма

Не входит и делается отдельно, если понадобится: дельта-обновления, откат на
предыдущую версию, поэтапная раскатка по магазинам, полностью автоматическая
установка без участия кассира, подпись Authenticode, подпись манифеста
собственным ключом, автоматическая публикация манифеста из скрипта сборки.

Ни один из этих пунктов не требует переделки описанной схемы.
